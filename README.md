## Спорные места

### Можно ли отправить заново чек, который отклонили?

Нет. Уникальна связка ФН + ФД + ФП для всей базы, а не для пользователя и не для «активных» статусов. Фискальный документ один: повторная отправка тех же реквизитов - это тот же чек. Пользователь видит сообщение «Этот чек уже был зарегистрирован», а не 500. Ссылка «Попробовать» открывает форму для **другого** чека.

Если бы повтор разрешали, пришлось бы решать, что делать с уже сохранённой заявкой, кто виноват при гонке двух пользователей и как не превратить проверку в бесконечный цикл. Для акции проще и честнее: один фискальный чек - одна попытка.

### Как считать границы периода, если пользователь в другом часовом поясе?

Дата покупки - это календарная дата с бумажного/электронного чека. Пользователь вводит `ДД.ММ.ГГГГ`, сервер сравнивает её с `PROMOTION_START_DATE` и `PROMOTION_END_DATE` как с датами. Обе границы включительно: чек от 01.06.2026 и от 31.12.2026 проходит, если так задано в `.env`.

Часовой пояс акции — `Europe/Moscow`. Время на чеке в форме не спрашиваем, поэтому дата не «плавает» из‑за UTC: в базу она пишется как полдень по Москве. Так 1 июня остаётся 1 июня и для пользователя во Владивостоке, и для пользователя в Калининграде. Сдвигать окно акции под локальные часы пользователя не стали бы: иначе один и тот же чек был бы валиден в одном регионе и невалиден в другом.

### Что ещё зафиксировали

- На макете есть статус «Вы выиграли». В модели его нет, отдельный розыгрыш не делали. Показываем три статуса: на проверке, принят, отклонён.
- Регистрация — отдельная страница в виде карточки, как модальное окно на макете. Кнопка «Зарегистрировать чек» ведёт на форму, крестик и «На главную» — в кабинет.
- Минимальная сумма по заданию 1000 ₽, но тоже вынесена в `.env` (`MIN_RECEIPT_AMOUNT`), чтобы не плодить вторую зашитую константу рядом с датами.
- Сортировка колонок на макете декоративная. Список всегда от новых к старым по дате регистрации.

### Работа с ИИ
Использовал ChatGPT и Cursor (модель Cursor Grok 4.6 Medium). В частности ChatGPT использовался, грубо говоря, как браузер, уточнял разные моменты по документации Django, Python и вёрстки. Cursor доверил точечно создавать элементы макета, параллельно поправляю его либо своими руками. В основном ИИ-агенты ошибаются почему-то в выборе цветов, а так с хорошим промптом все выполняет как нужно. Если бы было больше времени, то конечно бы занялся рефакторингом, мне не совсем нравится качество и читаемость кода с точки зрения Clean Code, есть несоблюдения с принципами SOLID.
